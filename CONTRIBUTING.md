# Contributing

## Developer Certificate of Origin

Every commit must be signed off, which certifies the terms at https://developercertificate.org/:

    git commit -s

Pull requests with unsigned commits fail CI.

## Toolchain

- Go 1.26 or later to build the CLI and run the workspace; the runtime module itself supports Go 1.24
- pnpm 10 or later
- staticcheck: `go install honnef.co/go/tools/cmd/staticcheck@latest`

## Checks before pushing

    gofmt -l . && go vet ./... && staticcheck ./... && go test ./...
    cd cmd/bowline && go vet ./... && go test ./...
    pnpm install && pnpm check && pnpm test

## Golden files

Files under `spec/` are generated by tests. Regenerate with `go test ./contract -update` and commit the result.

## Contract changes

Pull requests that change an example's contract get a comment from the contract gate with every added, widened, narrowed, removed, or breaking change. A breaking change fails the check; if it is intended, say so in the pull request and set `allow-breaking` on the gate step.

## Releases

Every module and package in this repository shares one version number. `scripts/release-prep.sh vX.Y.Z` sets it everywhere, opens the changelog section, and prints the lockfile and regeneration commands to run after it. `scripts/verify.sh` runs the whole verification locally, and `scripts/tag-modules.sh vX.Y.Z` prints the tag commands.

Changesets is used only to publish: `changeset publish` pushes the npm packages whose version is not on the registry yet. Do not add a changeset to bump a version; the release script owns versions.
