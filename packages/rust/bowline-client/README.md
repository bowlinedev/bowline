# bowline-client

Runtime for Rust clients generated by [Bowline](https://github.com/bowlinedev/bowline) from a Go API contract. The generated `bowline.rs` carries the types, validation, and one method per procedure; this crate carries the transport, the error model, the codec helpers, and the validation rules.

```rust
use bowline_client::{CallOptions, Code, Error, Transport};

let client = bowline::Client::new(Transport::new("http://localhost:8080/api"));
match client.invoices().get(&bowline::GetInvoiceInput { id: 3 }, None).await {
    Ok(invoice) => println!("{}", invoice.total),
    Err(Error::Remote(e)) if e.code == Code::NotFound => println!("no such invoice"),
    Err(e) => return Err(e.into()),
}
```

`Transport::call` validates the input first and returns `Error::Invalid` with the same issue paths and messages the server would produce, so a bad request never leaves the process. Server failures arrive as `Error::Remote` with the code, HTTP status, message, declared variant name, details, and issues; `Error::Transport` wraps connection failures, `Error::Decode` a body that does not match the contract. A per-call timeout from `CallOptions::timeout` is reported as `Error::Remote` with `Code::DeadlineExceeded` and status 0.

Subscriptions are `futures_core::Stream`s over server-sent events and uploads take a `reqwest::Body` plus a file name. String-encoded 64-bit integers and base64 bytes use the `codec` modules on fields and the `StringInt`, `StringUint`, and `Base64Bytes` newtypes inside collections.
